# HACKALEM AI — консультант ekt.kz

Рабочий прототип: FastAPI + веб-чат на HTML/JS, клиент реального API ekt.kz, поиск по кэшируемому каталогу, характеристики/сертификаты, подбор аналогов, защищённая локальная корзина. Без ключа OpenAI работает ограниченный детерминированный режим; с ключом — выбор инструментов через нативный Function Calling.

## Быстрый запуск

Python 3.11+. Команды ниже для PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Открыть http://127.0.0.1:8000 — чат; `/cart` — корзина; `/docs` — Swagger; `/health` — состояние. В Linux/macOS используйте `.venv/bin/python`. По умолчанию `EKT_MODE=demo`: никаких внешних запросов и никакого ключа для демонстрации не нужно. Для воспроизводимой установки на проверенном окружении есть `requirements.lock.txt`.

## Реальный каталог и ИИ

В `.env` установите `EKT_MODE=live`, `EKT_API_USER`, `EKT_API_PASSWORD` из доступа партнёра. Пароль не хранится в исходниках или примерах. Для свободного языка задайте `OPENAI_API_KEY` и при необходимости `OPENAI_MODEL` (по умолчанию `gpt-4.1-mini`, модель должна поддерживать Chat Completions tools и vision для JPEG). Наличие/доступность модели зависит от аккаунта. Без ключа используйте поиск, кнопки карточек и формат `Добавь <ID> <количество>`.

API проверен 23 сентября 2026: список содержит `items`, `page`, `per_page`, `count`. `count` — число элементов страницы, **не общее число товаров**. Карточка содержит `quantity`, `stores`, `properties`, `description`. Значения `quantity` преобразуются в `stock`; отсутствие остатка не считается нулём. Ссылки сертификатов принимаются только с HTTPS-хоста ekt.kz. Поле сертификатов в проверенной карточке отсутствовало: код не придумывает документ.

По умолчанию загружается до 5 страниц (обычно 100 товаров), при достижении лимита результат помечается как частичный. Можно увеличить `CATALOG_MAX_PAGES`, но первый поиск станет медленнее. По ID детальная карточка доступна вне выборки. По артикулу поиск ограничен загруженной выборкой. Загрузка страниц последовательная; повторяющиеся страницы останавливают обход. Кэш списка 900 секунд, карточек 60 секунд. На явной проверке наличия и перед подтверждением корзины карточка запрашивается заново. При сбое API сервер возвращает понятную ошибку; не подменяет реальные данные синтетическими и не выдаёт устаревшие остатки как актуальные.

В карточке 515291 обнаружен конфликт: название/описание — 160 А, `NOMINALNYY_TOK` — 250 А. Прототип показывает предупреждение, блокирует добавление такой позиции и не использует её для аналогов. Это пример проверки одного типа противоречий, не универсальная верификация электротехнических данных.

## Архитектура

```text
Браузер (чат / карточки / корзина)
  → FastAPI: HttpOnly session cookie + CSRF
    → Agent: выбор инструментов LLM либо ограниченный маршрутизатор
      → Catalog → EktClient → ekt.kz (BasicAuth, таймауты, повторы)
      → CartService: предложение → явное подтверждение → свежий остаток
```

* `app/ekt.py`: httpx-клиент с BasicAuth, ограниченными повторами сетевых ошибок/429/5xx; редиректы отключены. Авторизация никогда не отправляется по ссылкам из каталога.
* `app/catalog.py`: TTL-кэш, защита от одновременной загрузки списка, поиск по словам/артикулу/ID, консервативные аналоги.
* `app/agent.py`: отдельные инструменты `search_products`, `get_product_details`, `check_stock`, `find_analogs`, `purchase_terms`, `prepare_cart_addition`. Pydantic проверяет аргументы. ИИ не генерирует фактический текст о товарах: сервер отображает результаты инструментов. История до 12 сообщений; до 3 раундов инструментов за запрос.
* `app/cart.py`: серверное предложение на 5 минут, привязанное к сессии, товару, количеству и цене. `add_to_cart` не предоставлен LLM: его вызывает только сервер после подтверждения клиента.
* `app/uploads.py`: извлечение текста из вложений в памяти, без сохранения файлов.
* `app/main.py`: HTTP-маршруты, сессии, CSRF, ограничения, обработка ошибок.
* `static/`: адаптивный интерфейс без сборки и внешних скриптов. Весь недоверенный текст выводится через `textContent`.

LLM подключён по официальной схеме [OpenAI Function Calling](https://developers.openai.com/api/docs/guides/function-calling). LangChain и векторная БД для этого масштаба не нужны; текущий поиск лексический. Векторный поиск можно добавить перед ранжированием кандидатов, сохранив точную проверку характеристик.

## Подтверждение и корзина

1. Пользователь выбирает товар и количество. `/api/cart/proposals` создаёт предложение, не меняя корзину.
2. Кнопка «Да, добавить» отправляет `/api/cart/confirm` с ID предложения и строгим JSON-boolean `confirmed: true`. Также принимаются отдельные сообщения `Да`, `Да, добавь`, `Да добавь`, `Подтверждаю` при активном предложении.
3. Сервер повторно получает карточку. Проверяет цену, неизвестные значения, конфликты, минимальную партию/кратность и **сумму уже добавленного и нового количества** относительно stock. При изменении цены нужно новое подтверждение.
4. Изменение корзины сериализовано блокировкой сессии. Повтор того же подтверждения не удваивает количество. Чужие/истёкшие/заменённые предложения отклоняются. Любое другое сообщение отменяет прежнее предложение; текст вложения не может подтвердить покупку.
5. Ответ содержит `/cart`, открывающий актуальное состояние **той же сессии**. Ссылка без cookie не даёт доступа к чужой корзине.

Это демонстрационная корзина в памяти, не реальная корзина ekt.kz. API записи в корзину партнёром не предоставлен. Нет оплаты, заказа, резерва или списания остатков. Для подключения реального сайта нужен его серверный API корзины/авторизации и атомарная проверка/резервирование наличия на стороне магазина; конкурентные покупки разных покупателей этот прототип не резервирует.

## Данные и аналоги

`data/demo.json` — пять синтетических товаров с явно обозначенными названиями и артикулами. Цены/склады вымышлены. DEMO-C16-A отсутствует, DEMO-C16-B подходит по ключевым характеристикам и есть в наличии; DEMO-C25 отличается током и исключается.

Аналоги допускаются только внутри одной категории, при наличии минимум трёх известных критических характеристик источника и совпадении всех известных критических полей. Проверяются до 20 кандидатов, возвращаются до 3 доступных. При нехватке данных или конфликте — обращение к менеджеру, а не обещание совместимости. Это ограниченный подбор, не инженерное заключение; монтаж и дополнительные параметры требуют проверки. В live-каталоге подходящего аналога может не быть в выборке.

`KRATNOST_MIN` интерпретируется как минимальная партия и кратность. Если отсутствует — **демонстрационное допущение 1**, которое нужно согласовать с партнёром. Количество и деньги представлены `Decimal`; поддерживаются дробные количества до 3 знаков, если это допускает кратность.

Подтверждённые правила оплаты и доставки не предоставлены. Инструмент сообщает об этом честно и объясняет источник минимальной партии. Для полного бизнес-сценария внесите согласованную базу правил партнёра в `purchase_terms`. Прототип не заявляет вымышленные сроки или тарифы.

## Вложения и приватность

Поддерживаются PDF с текстовым слоем (до 30 страниц), DOCX, XLSX (первые 5 листов, 300 строк × 20 столбцов), JPEG. Файл до 5 МБ, извлечённый текст ограничен 16 000 символов. DOC/XLS нужно пересохранить в DOCX/XLSX; OCR сканированных PDF не включён. JPEG требует OpenAI: изображение уменьшается, очищается пересохранением и передаётся модели для чтения маркировки. Результат распознавания нужно сверить.

Вложения — только поисковый контекст. Автоматического массового добавления из спецификации нет: каждая выбранная позиция проходит предложение и подтверждение. Файлы не сохраняются, но при включённом ИИ текст вложений и история текущей сессии отправляются OpenAI. Не вводите платёжные или персональные данные. Прототип не умеет надёжно обнаруживать/редактировать случайно введённые секреты: перед публичным использованием нужны DLP/редакция, согласие на обработку и политика хранения провайдера. Тела запросов и документы не логируются приложением.

## Демонстрация за 2 минуты

1. `DEMO-C16-A` → нулевой остаток, характеристики, аналог DEMO-C16-B с объяснением.
2. `Добавь demo-102 2` → предложение, корзина пуста.
3. `Нет` → корзина не меняется.
4. Повторите запрос и ответьте `Да, добавь` → 2 единицы и ссылка `/cart`.
5. `Добавь demo-102 11` → отказ: 2 уже в корзине, остаток 12.
6. `Условия оплаты и доставки?` → честный ответ о недостающих правилах.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют реальную форму ответа API через фикстуры/MockTransport, BasicAuth, пагинацию, кэш, таймауты/ошибки, аналоги, неизвестный остаток, конфликт характеристик, безопасные ссылки сертификатов, отсутствие записи до подтверждения, подмену/повтор/истечение предложения, CSRF, чужие сессии, изменение остатка/цены, суммарное количество, конкурентные подтверждения, DOCX/XLSX. Тесты не вызывают платные API и не изменяют магазин. Фактический вызов LLM и распознавание JPEG требуют отдельной проверки с вашим ключом.

Проверено локально на Python 3.14: 25 тестов успешно (24 основных и отдельный тест LLM через MockTransport). Последний проверяет, что модель может лишь предложить добавление, а выдуманный ею текст о цене не попадёт в ответ. Есть предупреждение Starlette о будущем переходе TestClient с httpx на httpx2; текущие проверки проходят. В браузере проверен путь от поиска до подтверждения и корзины с двумя товарами. Реальный Python-клиент также проверен на одной странице и карточке 515291. Повторить проверку реального API после заполнения `.env`: `python -m scripts.smoke_live`.

## Ограничения и следующий шаг

Запускайте **один worker**: сессии, кэш, блокировки и корзины живут в памяти и пропадают после рестарта. До 1000 сессий, срок жизни по умолчанию час, история ограничена. Для нескольких процессов нужны Redis/БД и транзакционная корзина. Для публичного размещения нужны HTTPS (`COOKIE_SECURE=true`), ограничения скорости/размера тела на reverse proxy, отдельный изолированный процесс парсинга файлов, мониторинг и собственная база проверенных правил магазина. Встроенный лимит Content-Length не заменяет потоковый лимит proxy.

Задержка в единицы секунд возможна для прогретого кэша/режима без LLM, но не гарантирована: холодная загрузка, повторные сетевые запросы, поиск аналогов и раунды LLM могут быть дольше. Подготовьте каталог перед демо. Следующий практический шаг — согласовать API реальной корзины, правила покупки, поля сертификатов, единицы измерения и критерии аналогов с партнёром.
