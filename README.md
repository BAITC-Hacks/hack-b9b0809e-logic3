# HACKALEM AI — консультант ekt.kz

Рабочий прототип: FastAPI + веб-чат на HTML/JS, клиент реального API ekt.kz, поиск по кэшируемому каталогу, характеристики/сертификаты, подбор аналогов, защищённая локальная корзина. Без ключа OpenAI работает ограниченный детерминированный режим; с ключом — выбор инструментов через нативный Function Calling.

## Быстрый запуск

Python 3.11+. Команды ниже для PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Открыть http://127.0.0.1:8000 — чат; `/cart` — корзина; `/docs` — Swagger; `/health` — состояние. В Linux/macOS используйте `.venv/bin/python`. По умолчанию `EKT_MODE=demo`: никаких внешних запросов и никакого ключа для демонстрации не нужно. Для воспроизводимой установки на проверенном окружении есть `requirements.lock.txt`.

## Реальный каталог и ИИ

В `.env` установите `EKT_MODE=live`, `EKT_API_USER`, `EKT_API_PASSWORD` из доступа партнёра. Пароль не хранится в исходниках или примерах. Для свободного языка задайте `OPENAI_API_KEY` и при необходимости `OPENAI_MODEL` (по умолчанию `gpt-4.1-mini`, модель должна поддерживать Chat Completions tools и vision для JPEG). Наличие/доступность модели зависит от аккаунта. Без ключа используйте поиск, кнопки карточек и формат `Добавь <ID> <количество>`.

API проверен 23 сентября 2026: список содержит `items`, `page`, `per_page`, `count`; параметр запроса `per_page=100` поддерживается. `count` — число элементов страницы, **не общее число товаров**. По умолчанию запрашиваем 100 товаров на страницу (`CATALOG_PAGE_SIZE`); изменение размера инвалидирует прежний кэш, чтобы не пропустить страницы. Карточка содержит `quantity`, `stores`, `properties`, `description`. Значения `quantity` преобразуются в `stock`; отсутствие остатка не считается нулём. Ссылки сертификатов принимаются только с HTTPS-хоста ekt.kz. Поле сертификатов в проверенной карточке отсутствовало: код не придумывает документ.

Live-режим загружает весь список товаров до пустой или неполной страницы. `CATALOG_MAX_PAGES=5000` — защитный предел, а не размер выборки; достижение предела без конца каталога явно отмечается как частичный результат. API не предоставляет общее количество товаров, поэтому число определяется завершённым обходом. До четырёх запросов одновременно (`CATALOG_CONCURRENCY`), таймаут ответа 30 секунд (`EKT_API_TIMEOUT_SECONDS`), ограниченные повторы при сетевых ошибках/429/5xx.

Перед первой демонстрацией загрузите каталог из терминала VS Code:

```powershell
.\.venv\Scripts\python.exe -m scripts.sync_catalog
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Команда выводит прогресс каждые 25 страниц. `data/catalog-cache.json` — полный нормализованный каталог; `data/catalog-cache.pages/` — исходные ответы страниц, включая поля, которые пока не используются интерфейсом. Оба исключены из Git. Недавние страницы повторно используются после прерывания загрузки. Для принудительной загрузки с начала: `python -m scripts.sync_catalog --force`. Не запускайте несколько синхронизаций одновременно. Источник кэша привязан к URL API и пользователю, пароль в кэш не записывается. Загрузка с ошибкой или достигнутым пределом не заменяет предыдущий полный файл.

При запуске сервер строит локальный поисковый индекс из сохранённого каталога. Срок кэша списка — 24 часа (`CATALOG_TTL_SECONDS=86400`). Устаревший список доступен для поиска, обновление запускается в фоне при запуске сервера или поиске; интерфейс сообщает об этом. Карточки найденных товаров отдельно запрашиваются у API с кэшем 60 секунд. Явная проверка наличия и подтверждение корзины всегда запрашивают свежую карточку. При недоступности карточки сервер возвращает ошибку, а не старую цену/остаток из выгрузки. Первый запуск без кэша начинает фоновую загрузку, поиск в это время сообщает прогресс. `/health` показывает число товаров/страниц, `catalog_syncing`, `catalog_stale`, `partial_catalog`, `catalog_error`. Если каталог ещё не загружен, `catalog_loaded=false`; поле `status=ok` обозначает доступность самого HTTP-сервера.

Поиск работает без OpenAI: точный ID и артикул имеют приоритет; конечный `_` в артикуле можно не вводить. Для обычного запроса требуются все значимые слова, поддерживаются распространённые названия брендов, `АВ`/«автомат», `16 А`/`16A`, размеры `3х2,5`/`3x2.5`. Числовые параметры сравниваются целиком: `16А` не совпадает с `160А`. Это лексический поиск с небольшим словарём синонимов, без универсальной коррекции опечаток и понимания произвольных фраз. Подробные характеристики, склады и сертификаты поступают по запросу карточек, а не посредством массовых десятков тысяч вызовов detail. API даёт доступ к каталогу, не к внутренней базе клиентов/заказов.

В карточке 515291 обнаружен конфликт: название/описание — 160 А, `NOMINALNYY_TOK` — 250 А. Прототип показывает предупреждение, блокирует добавление такой позиции и не использует её для аналогов. Это пример проверки одного типа противоречий, не универсальная верификация электротехнических данных.

## Архитектура

### Аккаунты и профили

Страница `/profile` открывает вход/регистрацию для гостя и личный кабинет для пользователя. Доступны регистрация по имени, email и паролю; вход, выход; редактирование имени, телефона, города и компании; смена пароля с проверкой текущего. Необязательные контактные поля можно очистить. Начальная аватарка составляется из инициалов. Интерфейс адаптируется к мобильному экрану, поддерживает клавиатуру, менеджеры паролей и показ/скрытие пароля. Переход между чатом, корзиной и профилем сохраняет DOM открытого чата.

Это отдельные аккаунты **EKT Ассистента**, не авторизация на основном сайте ekt.kz. Email нормализуется без учёта регистра и служит уникальным логином. Проверка существования/владения почтой, смена email и восстановление забытого пароля пока не подключены: для них нужны почтовый провайдер и одноразовые подтверждения. Интерфейс не показывает email как подтверждённый и не предлагает неработающую кнопку восстановления.

* `app/accounts.py` — SQLite-схема, валидация профиля, Argon2id, постоянные сессии, ограничение попыток.
* `app/auth.py` — маршруты аккаунтов. Эти действия не включены в инструменты ИИ.
* `static/account.js`, `static/account.css`, `static/profile.html` — отдельный модуль личного кабинета.
* `tests/test_accounts.py` — проверки регистрации, доступа, сессий, лимитов и смены пароля.

Настройки: `AUTH_DB_PATH=data/accounts.sqlite3`, `AUTH_TTL_SECONDS=604800` (7 дней), `COOKIE_SECURE=true` при размещении на HTTPS. База и её WAL/SHM-файлы исключены из Git; аккаунты, профиль и вход переживают перезапуск. Для резервного копирования работающей БД используйте SQLite backup API, не копируйте только основной файл без WAL. Изменение пути создаст другую базу. Схема имеет `user_version=1`; дальнейшие изменения таблиц потребуют миграций.

Пароли длиной 12–128 символов хешируются Argon2id с параметрами библиотеки (включая случайную соль); при входе предусмотрено обновление устаревшего хеша. Cookie `ekt_auth` содержит случайный токен, в SQLite — только SHA-256 этого токена и срок действия. Cookie имеет `HttpOnly`, `SameSite=Strict` и `Secure` согласно настройке окружения. CSRF-токен обязателен для всех изменений, включая регистрацию и вход. Сообщение неуспешного входа одинаково для неверного пароля и неизвестного email. Ошибки валидации не возвращают введённые пароли. На действие действует лимит 8 попыток на идентификатор и 30 на IP за 15 минут; он хранится в SQLite. IP берётся из соединения ASGI; за proxy настройте доверенные адреса uvicorn, не доверяйте произвольному `X-Forwarded-For`. Одновременно выполняются не более двух операций хеширования на процесс.

При входе, выходе и смене пароля меняются cookie временной сессии и CSRF. Временные чат, вложение и демонстрационная корзина сбрасываются на границе аккаунта, чтобы данные предыдущего пользователя не достались следующему. Смена пароля отзывает все прежние сессии, включая другие устройства, и выдаёт новый токен текущему браузеру. Вкладки того же браузера получают уведомление о смене аккаунта и обновляются. Уже отозванная/истёкшая сессия не может изменять профиль. **История диалогов в БД не сохраняется**; для будущего этапа у аккаунта есть постоянный `id`.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/auth/me` | Текущий профиль или `user: null` для гостя |
| `POST /api/auth/register` | Создать аккаунт и войти |
| `POST /api/auth/login` | Войти по email и паролю |
| `POST /api/auth/logout` | Отозвать текущую сессию |
| `POST /api/auth/profile` | Изменить только свой профиль |
| `POST /api/auth/password` | Сменить пароль, завершить остальные сеансы |

Установка новых зависимостей в существующее окружение: `.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt`. Затем перезапустите uvicorn. HTTP-тесты выполняются на временной SQLite-базе и не затрагивают настоящие аккаунты. Основа защиты: [рекомендации OWASP по аутентификации](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) и [документация argon2-cffi](https://argon2-cffi.readthedocs.io/en/25.1.0/api.html).

Проверено 23.09.2026: **58 тестов прошли**, зависимости совместимы (`pip check`). В браузере пройдены регистрация, редактирование контактов, выход и повторный вход; сохранённый профиль восстановился. Проверен экран шириной 390 px и сохранение открытого диалога при переходе в профиль и обратно. Синтетический аккаунт проверки удалён. Смена пароля, отзыв других устройств, истечение сессии, CSRF, лимиты попыток, разделение пользователей и одновременная регистрация одного email проверены HTTP/SQLite-тестами.

```text
Браузер (чат / карточки / корзина)
  → FastAPI: HttpOnly session cookie + CSRF
    → Agent: выбор инструментов LLM либо ограниченный маршрутизатор
      → Catalog → EktClient → ekt.kz (BasicAuth, таймауты, повторы)
      → CartService: предложение → явное подтверждение → свежий остаток
```

* `app/ekt.py`: httpx-клиент с BasicAuth, ограниченными повторами сетевых ошибок/429/5xx; редиректы отключены. Авторизация никогда не отправляется по ссылкам из каталога.
* `app/catalog.py`: полная пагинация с ограничением параллелизма, фоновое обновление, TTL-кэш карточек, консервативные аналоги.
* `app/catalog_store.py`: атомарное сохранение полного каталога и возобновляемый кэш исходных страниц.
* `app/search.py`: локальный инвертированный индекс, точные артикулы, пересечение слов запроса и нормализация электротехнических обозначений.
* `scripts/sync_catalog.py`: предварительная загрузка каталога с прогрессом, возобновлением и режимом `--force`.
* `app/agent.py`: отдельные инструменты `search_products`, `get_product_details`, `check_stock`, `find_analogs`, `purchase_terms`, `prepare_cart_addition`. Pydantic проверяет аргументы. ИИ не генерирует фактический текст о товарах: сервер отображает результаты инструментов. История до 12 сообщений; до 3 раундов инструментов за запрос.
* `app/cart.py`: серверное предложение на 5 минут, привязанное к сессии, товару, количеству и цене. `add_to_cart` не предоставлен LLM: его вызывает только сервер после подтверждения клиента.
* `app/uploads.py`: извлечение текста из вложений в памяти, без сохранения файлов.
* `app/main.py`: HTTP-маршруты, сессии, CSRF, ограничения, обработка ошибок.
* `static/`: адаптивный интерфейс без сборки и внешних скриптов. Весь недоверенный текст выводится через `textContent`.

LLM подключён по официальной схеме [OpenAI Function Calling](https://developers.openai.com/api/docs/guides/function-calling). LangChain и векторная БД для этого масштаба не нужны; текущий поиск лексический. Векторный поиск можно добавить перед ранжированием кандидатов, сохранив точную проверку характеристик.

## Подтверждение и корзина

1. Пользователь выбирает товар и количество. `/api/cart/proposals` создаёт предложение, не меняя корзину.
2. Кнопка «Да, добавить» отправляет `/api/cart/confirm` с ID предложения и строгим JSON-boolean `confirmed: true`. Также принимаются отдельные сообщения `Да`, `Да, добавь`, `Да добавь`, `Подтверждаю` при активном предложении.
3. Сервер повторно получает карточку. Проверяет цену, неизвестные значения, конфликты, минимальную партию/кратность и **сумму уже добавленного и нового количества** относительно stock. При изменении цены нужно новое подтверждение.
4. Изменение корзины сериализовано блокировкой сессии. Повтор того же подтверждения не удваивает количество. Чужие/истёкшие/заменённые предложения отклоняются. Любое другое сообщение отменяет прежнее предложение; текст вложения не может подтвердить покупку.
5. Ответ содержит `/cart`, открывающий актуальное состояние **той же сессии**. Ссылка без cookie не даёт доступа к чужой корзине.

В карточке товара количество можно менять кнопками `−` и `+` с шагом минимальной партии; первоначальное добавление по-прежнему требует подтверждения. На странице `/cart` кнопка `−` уменьшает количество конкретной позиции на этот шаг (последний шаг удаляет позицию), а нажатие `+` само является явным действием клиента и сразу добавляет один шаг. Сервер проверяет свежий остаток, цену и минимальную партию; при изменении цены/партии добавление отклоняется. Также можно удалить позицию целиком или очистить всю корзину. Изменения выполняются для текущей сессии через защищённые CSRF-запросы.

Это демонстрационная корзина в памяти, не реальная корзина ekt.kz. API записи в корзину партнёром не предоставлен. Нет оплаты, заказа, резерва или списания остатков. Для подключения реального сайта нужен его серверный API корзины/авторизации и атомарная проверка/резервирование наличия на стороне магазина; конкурентные покупки разных покупателей этот прототип не резервирует.

## Данные и аналоги

Переходы между чатом и `/cart` выполняются без перезагрузки страницы. Кнопки браузера «Назад»/«Вперёд» и ссылка «Вернуться к подбору» сохраняют переписку, карточки, выбранные количества, черновик и положение прокрутки. Корзина при переходе обновляется с сервера. Состояние чата живёт в текущей вкладке: полное обновление страницы (F5), новая вкладка или закрытие страницы начинают новый интерфейс чата. Долговременное хранение переписки не включено.

`data/demo.json` — пять синтетических товаров с явно обозначенными названиями и артикулами. Цены/склады вымышлены. DEMO-C16-A отсутствует, DEMO-C16-B подходит по ключевым характеристикам и есть в наличии; DEMO-C25 отличается током и исключается.

Аналоги допускаются только внутри одной категории, при наличии минимум трёх известных критических характеристик источника и совпадении всех известных критических полей. Проверяются до 20 кандидатов, возвращаются до 3 доступных. При нехватке данных или конфликте — обращение к менеджеру, а не обещание совместимости. Это ограниченный подбор, не инженерное заключение; монтаж и дополнительные параметры требуют проверки. В live-каталоге подходящего аналога может не быть в выборке.

`KRATNOST_MIN` интерпретируется как минимальная партия и кратность. Если отсутствует — **демонстрационное допущение 1**, которое нужно согласовать с партнёром. Количество и деньги представлены `Decimal`; поддерживаются дробные количества до 3 знаков, если это допускает кратность.

Подтверждённые правила оплаты и доставки не предоставлены. Инструмент сообщает об этом честно и объясняет источник минимальной партии. Для полного бизнес-сценария внесите согласованную базу правил партнёра в `purchase_terms`. Прототип не заявляет вымышленные сроки или тарифы.

## Вложения и приватность

Поддерживаются PDF с текстовым слоем (до 30 страниц), DOCX, XLSX (первые 5 листов, 300 строк × 20 столбцов), JPEG. Файл до 5 МБ, извлечённый текст ограничен 16 000 символов. DOC/XLS нужно пересохранить в DOCX/XLSX; OCR сканированных PDF не включён. JPEG требует OpenAI: изображение уменьшается, очищается пересохранением и передаётся модели для чтения маркировки. Результат распознавания нужно сверить.

Вложения — только поисковый контекст. Автоматического массового добавления из спецификации нет: каждая выбранная позиция проходит предложение и подтверждение. Файлы не сохраняются, но при включённом ИИ текст вложений и история текущей сессии отправляются OpenAI. Не вводите платёжные или персональные данные. Прототип не умеет надёжно обнаруживать/редактировать случайно введённые секреты: перед публичным использованием нужны DLP/редакция, согласие на обработку и политика хранения провайдера. Тела запросов и документы не логируются приложением.

## Демонстрация за 2 минуты

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют реальную форму ответа API через фикстуры/MockTransport, BasicAuth, пагинацию, кэш, таймауты/ошибки, аналоги, неизвестный остаток, конфликт характеристик, безопасные ссылки сертификатов, отсутствие записи до подтверждения, подмену/повтор/истечение предложения, CSRF, чужие сессии, изменение остатка/цены, суммарное количество, конкурентные подтверждения, DOCX/XLSX. Тесты не вызывают платные API и не изменяют магазин. Фактический вызов LLM и распознавание JPEG требуют отдельной проверки с вашим ключом.

Тесты синхронизации дополнительно проверяют обход дальше пяти страниц, отсутствие зависимости от `count`, восстановление после перезапуска без сети, изоляцию источников кэша, повторяющиеся страницы, сохранение предыдущего каталога при сбое, возобновление по страницам, частичный результат на лимите и работу поиска во время неудачного фонового обновления. Поиск проверяется на точных артикулах и несовместимых числовых параметрах. Все тесты используют отдельный временный каталог и не меняют локальную live-выгрузку. Проверку реального API после заполнения `.env` можно повторить командой `python -m scripts.smoke_live`.

Сервер восстановил каталог с диска (`partial_catalog=false`). ## Ограничения и следующий шаг

Запускайте **один worker**: сессии, кэш, блокировки и корзины живут в памяти и пропадают после рестарта. До 1000 сессий, срок жизни по умолчанию час, история ограничена. Для нескольких процессов нужны Redis/БД и транзакционная корзина. Для публичного размещения нужны HTTPS (`COOKIE_SECURE=true`), ограничения скорости/размера тела на reverse proxy, отдельный изолированный процесс парсинга файлов, мониторинг и собственная база проверенных правил магазина. Встроенный лимит Content-Length не заменяет потоковый лимит proxy.

Задержка в единицы секунд возможна для прогретого кэша/режима без LLM, но не гарантирована: холодная загрузка, повторные сетевые запросы, поиск аналогов и раунды LLM могут быть дольше. Подготовьте каталог перед демо. Следующий практический шаг — согласовать API реальной корзины, правила покупки, поля сертификатов, единицы измерения и критерии аналогов с партнёром.
